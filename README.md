# Ragdoll Punch Simulator

A Roblox simulator: train Power, equip gloves, hatch and upgrade pets, punch a ragdoll down a runway for Wins, rebirth for multipliers and unlock five worlds.

The code lives in this repository and syncs into Roblox Studio with [Rojo](https://rojo.space). The worlds are generated by code when the server starts, so you don't need to build anything by hand or import any assets.

## Quick start

### One-time setup

1. **Install Git:** https://git-scm.com/download/win
2. **Install Rokit**, the tool manager that installs the right Rojo version. In PowerShell:
   ```powershell
   Invoke-RestMethod https://raw.githubusercontent.com/rojo-rbx/rokit/main/scripts/install.ps1 | Invoke-Expression
   ```
   Then open a **new** terminal.
3. **Install the tools.** From the repository folder:
   ```powershell
   rokit install
   rojo --version      # should print Rojo 7.7.1
   ```
4. **Install the Rojo Studio plugin.** Close Roblox Studio first, then run:
   ```powershell
   rojo plugin install
   ```

### Every time you work on the game

1. Open Roblox Studio and create a new **Baseplate** place, or open the game's place.
2. In this folder, run the following and leave it running:
   ```powershell
   rojo serve
   ```
3. In Studio, click **Plugins → Rojo → Connect**. Check the list of changes Rojo shows you, then accept.
4. Press **Play**. You spawn in Greenfield Meadows.
5. Edit files in `src/`. Studio updates a moment after you save.

### Testing saving (DataStores)

Studio can't use DataStores until you allow it:

1. Publish the place: **File → Publish to Roblox**.
2. Open **Game Settings → Security** and turn on **Enable Studio Access to API Services**.

Without this the game still runs, but nothing is saved. The Output window and an in-game message both say when that's the case.

### Automated tests

When you press Play in Studio, the server runs every test in `ServerScriptService/Tests` and prints the results to **Output**. Look for `[Tests] All N tests passed.` The tests cover config validation, zone lookup, launch math, egg odds, glove purchases, pet fusion, rebirths, upgrades, worlds, launch rewards and save repair. To turn them off, set `RunTestsInStudio = false` in `GameConfig`.

## How to play

| Action | Where |
|---|---|
| Train Power | **TRAIN** button at the bottom. Hold it to keep training. |
| Punch the dummy | Walk to the dummy at the end of the hub and press **E** (or tap the prompt). Release the meter in the gold zone for a **Perfect** punch. |
| Buy gloves | 🥊 Glove Shop station or menu |
| Hatch pets | 🥚 Egg station or menu |
| Upgrade pets | ✨ Pet Upgrader. 5 identical pets → Gold → Diamond → Rainbow |
| Choose a bag | 🏋️ Training Area bags or the Bags menu |
| Rebirth | ♻️ Rebirth altar or menu |
| Token upgrades | ⬆️ Upgrades station or menu |
| New worlds | 🌍 World portal or menu |

## Project layout

| Folder | In Studio | Contents |
|---|---|---|
| `src/ReplicatedStorage/Shared/Config/` | `ReplicatedStorage.Shared.Config` | **All game data**: worlds, zones, gloves, pets, eggs, bags, upgrades, rebirths, launch tuning |
| `src/ReplicatedStorage/Shared/Logic/` | `ReplicatedStorage.Shared.Logic` | Formulas used by both sides (Power, launch distance, zone lookup, egg odds) |
| `src/ReplicatedStorage/Shared/Utilities/` | | Logging and number formatting |
| `src/ServerScriptService/Services/` | `ServerScriptService.Services` | One service per system. Each one handles its remotes and calls `Logic/Economy` |
| `src/ServerScriptService/Logic/` | | `Economy` (every progress change) and `DataTemplate` (save schema + migrations) |
| `src/ServerScriptService/World/` | | World generator and ragdoll builder |
| `src/ServerScriptService/Tests/` | | Tests that run in Studio |
| `src/StarterPlayer/StarterPlayerScripts/Controllers/` | `StarterPlayerScripts.Controllers` | Client controllers: UI, training, launch, pets, world |
| `src/StarterPlayer/StarterPlayerScripts/UI/` | | UI components, HUD and one file per panel |

`ReplicatedStorage.Remotes` is created by the server when it starts. Remote names are listed in `Shared/Remotes.luau`.

[docs/ARCHITECTURE.md](docs/ARCHITECTURE.md) explains how the systems fit together and how to balance the game.

## Rojo and Studio

- Rojo manages these folders: `ReplicatedStorage`, `ServerScriptService` and `StarterPlayer.StarterPlayerScripts`. Anything you add to those in Studio is **kept** (`$ignoreUnknownInstances`), but scripts that Rojo manages are overwritten by the files here on every sync. **Always edit code in `src/`, not in Studio.**
- The worlds are built under `Workspace.Worlds` when the game runs, not saved into the place. To change them, edit `World/WorldBuilder.luau`.
- Back up a place before connecting Rojo to it for the first time (**File → Save to File As…**).
